Lower-fee ordering recommendation

Recommended launch path

Start with direct pay-at-pickup or Stripe Checkout. This avoids marketplace commission and keeps the order relationship owned by Kochi. Card processing still costs money, but it is typically processor-fee only rather than a percentage marketplace tax on top.

Lowest operational friction

Phase 1: this website collects the order, then sends an email/SMS to the restaurant. Customer pays at pickup. Cost: Vercel hosting + optional email/SMS usage. Downside: more manual confirmation.

Best direct card payment path

Phase 2: add Stripe Checkout. The API creates a checkout session, Stripe handles payment, webhook confirms paid order, then email/SMS sends kitchen-ready receipt. Cost: normal card processing, no Menu11-style sales commission.

Restaurant ops path

If they need kitchen tickets/POS sync, use a lightweight middleware later: Square, Toast integration partner, Zapier/Make to Google Sheets, or a small Supabase order dashboard. Do not build full POS replacement until order volume proves the need.

Pitch line

“Your current ordering works, but every order rents the customer relationship. This direct system makes Kochi Po-cha the brand, keeps customer data in-house, and reduces per-order platform leakage.”
